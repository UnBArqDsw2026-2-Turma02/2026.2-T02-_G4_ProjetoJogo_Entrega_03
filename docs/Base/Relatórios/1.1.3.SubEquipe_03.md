### Metodologia do Foco 03

O desenvolvimento do presente foco iniciou-se partir do modelo estático da Entrega 02 ([Diagrama de Classes da SubEquipe 03](https://unbarqdsw2026-2-turma02.github.io/2026.2-T02-_G4_ProjetoJogo_Entrega_02/#/Base/Relat%C3%B3rios/1.1.3.SubEquipe_03?id=modelo-est%c3%a1tico)), tomando como referência a literatura sobre Padrões de Projeto Comportamentais GoF (*Gang of Four*) ([GAMMA et al., 1994; SHVETS, 2021](../Relatórios/1.1.3.SubEquipe_03.md#referências)) e as orientações da disciplina ([SERRANO, 2026](../Relatórios/1.1.3.SubEquipe_03.md#referências)). O trabalho envolveu a análise de requisitos, a modelagem em UML e a implementação em Java, com revisões ao longo do processo para manter a correspondência entre as estruturas propostas e o comportamento esperado do sistema.

#### 1. Análise de requisitos e identificação dos padrões

A equipe analisou o Diagrama de Classes da Entrega 02 para identificar pontos em que a aplicação de padrões comportamentais poderia reduzir o acoplamento entre componentes e organizar responsabilidades. Essa análise resultou na *Proposta de Padrões GoF Comportamentais*, que considerou quatro padrões:

- **Observer:** notificação da conclusão de atividades, como sessões Pomodoro, hábitos e acompanhamento da hidratação, para atualizar o `PetVirtual` e o gerenciamento de conquistas.
- **State:** organização das transições da `SessaoPomodoro`, incluindo configuração, foco, pausas e conclusão, e das fases de vida do `PetVirtual`.
- **Strategy:** separação das fórmulas de cálculo de experiência (XP), permitindo variar a estratégia conforme a categoria da atividade.
- **Memento:** captura e restauração do estado do `PetVirtual`, com o propósito de preservar informações por meio de *snapshots*.

A análise serviu para comparar alternativas de organização do comportamento do sistema e definir as estruturas que seriam modeladas.

#### 2. Prototipação em PlantUML e ferramentas de apoio

A prototipação dos diagramas foi feita em PlantUML. Weverton Rodrigues iniciou a modelagem dos padrões Observer e State, enquanto Pablo Cunha ficou responsável pelo Strategy e Arthur Mendes, pelo Memento.

O NotebookLM foi utilizado para consultar materiais da disciplina, incluindo slides e vídeos da professora (SERRANO, 2026), e o livro *Dive Into Design Patterns* ([SHVETS, 2021](../Relatórios/1.1.3.SubEquipe_03.md#referências)). O ChatGPT foi empregado para resolver dúvidas pontuais sobre a sintaxe do PlantUML e a disposição dos elementos nos diagramas. As sugestões foram revisadas pela equipe, que corrigiu estruturas incompatíveis com os requisitos e as abstrações do sistema.

### GoF Comportamental

### Observer

##### Contexto (Problema)

No utilitário gamificado de produtividade e acompanhamento de rotinas, a conclusão de atividades, como finalizar uma sessão na SessaoPomodoro, realizar o check-in diário de um Habito ou registrar o consumo de água em ContagemDeAgua, deve atualizar outros módulos do sistema. Entre eles estão o PetVirtual, que recebe experiência (XP), e o GerenciadorConquistas, responsável por verificar o cumprimento de metas.

Se cada classe de atividade precisasse chamar diretamente as operações do pet e do gerenciador de conquistas, haveria um acoplamento forte entre esses componentes. A inclusão de novos módulos para acompanhar o progresso, como um ranking semanal ou um histórico de atividades, também exigiria alterações nas classes existentes.

Para evitar essas dependências, foi adotado o padrão comportamental Observer (GoF). A proposta é estabelecer um mecanismo de publicação e assinatura (Publisher/Subscriber), no qual a atividade concluída emite um evento, representado por EventoConclusaoAtividade. Os observadores inscritos recebem a notificação e executam suas próprias ações, sem que a atividade precise conhecer suas implementações concretas.

##### Modelagem (Notação UML)

A modelagem do Observer foi feita em PlantUML e revisada para destacar os participantes do padrão e suas responsabilidades na notificação de atividades concluídas. O diagrama apresenta a estrutura de publicação e assinatura, separando o mecanismo de notificação das demais regras de negócio.

```java
package observer;

import java.util.ArrayList;
import java.util.List;

public abstract class AssuntoAtividade {

    private final List<ObservadorAtividade> observadores =
            new ArrayList<>();

    public void adicionarObservador(ObservadorAtividade obs) {
        if (obs != null && !observadores.contains(obs)) {
            observadores.add(obs);
        }
    }

    public void removerObservador(ObservadorAtividade obs) {
        observadores.remove(obs);
    }

    protected void notificarObservadores(
            EventoConclusaoAtividade evento) {

        List<ObservadorAtividade> copia =
                new ArrayList<>(observadores);

        for (ObservadorAtividade observador : copia) {
            observador.emAtividadeConcluida(evento);
        }
    }
}
```

### State

##### Contexto (Problema)

Na aplicação, duas entidades têm comportamentos que mudam conforme seu estado atual: a `SessaoPomodoro`, que passa pelas etapas de configuração, foco, pausa e conclusão, e o `PetVirtual`, que evolui pelas fases de bebê, criança, adolescente e adulto.

Sem uma estrutura para organizar essas mudanças, seria necessário espalhar condicionais (`if/else` ou `switch/case`) pelos métodos que controlam a sessão e o desenvolvimento do pet. Com isso, as classes de contexto acumulariam regras de diferentes estados, tornando a manutenção mais difícil e a inclusão de novos comportamentos dependente de alterações no código existente.

Para organizar essa lógica, foi adotado o padrão comportamental **State (GoF)**. Cada estado é representado por uma classe própria, responsável pelas ações e transições que lhe correspondem. As classes de contexto (`SessaoPomodoro` e `PetVirtual`) mantêm uma referência ao estado ativo (`estadoAtual`) e delegam a execução das operações a ele. Assim, as regras de cada etapa ficam separadas, e novos estados podem ser adicionados sem concentrar toda a lógica nas classes de contexto.

##### Modelagem (Notação UML)

A modelagem do padrão State foi elaborada em PlantUML para representar os participantes do padrão e suas relações nos dois módulos do sistema: o ciclo Pomodoro e a evolução do pet virtual.

Em ambos, as classes de contexto mantêm uma referência ao estado atual e delegam as operações às classes de estado concretas. Cada uma implementa o comportamento correspondente à etapa em que o objeto se encontra e define as transições para os demais estados.

### Strategy

##### Contexto (Problema)

No utilitário gamificado de produtividade e acompanhamento de rotinas, a conclusão de diferentes tipos de atividades — como finalizar um ciclo de foco na SessaoPomodoro, realizar o check-in diário de um Habito ou registrar o consumo de água em ContagemDeAgua — resulta na geração de pontos de experiência (XP). 
No entanto, cada modalidade de atividade possui uma lógica e uma fórmula de pontuação totalmente distintas: o ciclo Pomodoro calcula a experiência com base no tempo focado e nos ciclos concluídos, os hábitos aplicam multiplicadores progressivos conforme a sequência de dias mantida (\*streak\*), e o registro de água pontua de acordo com o volume consumido e o percentual da meta diária alcançado.

Se os algoritmos de cálculo fossem codificados diretamente dentro das classes de cada atividade ou estruturados por meio de condicionais rígidas, qualquer alteração no balanceamento do jogo, ajuste de fórmulas ou criação de regras dinâmicas (como eventos temporários de "XP em dobro") exigiria a modificação direta do código-fonte das entidades de domínio. Essa abordagem aumentaria o acoplamento, violando o princípio Aberto/Fechado (OCP) e o princípio de Responsabilidade Única (SRP), além de dificultar a manutenção do sistema.
 
Para resolver essa rigidez, foi adotado o padrão comportamental **Strategy (GoF)**. A solução isola cada algoritmo de pontuação em classes de estratégia separadas (`CalculoXPPomodoroStrategy`, `CalculoXPHabitoStrategy`, `CalculoXPAguaStrategy`), que implementam a interface comum `CalculoXPStrategy`. A classe abstrata de contexto (`AssuntoAtividade\`) mantém uma referência para essa interface e delega a execução do cálculo a ela. Dessa forma, as fórmulas de cálculo de XP tornam-se intercambiáveis e independentes, permitindo alterar ou adicionar novas estratégias de pontuação em tempo de execução sem modificar as classes de atividade existentes.



##### Modelagem (Notação UML)
A modelagem do padrão Strategy demonstra as classes de domínio (Contexto) relacionando-se por agregação com a interface `CalculoXPStrategy`. As estratégias concretas implementam essa interface, encapsulando as regras específicas de negócio para o cálculo de pontuação de forma isolada.

### Memento

##### Contexto (Problema)

No ecossistema do aplicativo de produtividade e gamificação, o `PetVirtual` evolui e acumula experiência (XP) de forma contínua com base nas interações do usuário e na conclusão de atividades. Contudo, em virtude de regras de negócio estritas — como a falha no cumprimento diário de metas, a interrupção brusca de um ciclo Pomodoro ou a quebra de uma ofensiva (*streak*) em um `Habito` —, o pet fica sujeito a penalidades severas, correndo o risco de perder parte vital de seu progresso e atributos alcançados.

Caso o sistema realizasse alterações diretas no estado do pet para gerenciar ou reverter essas penalidades sem um mecanismo de salvamento estruturado, a recuperação de dados perdidos exigiria recálculos complexos e acesso direto a atributos internos sensíveis. Isso violaria frontalmente o princípio do encapsulamento da Orientação a Objetos, aumentando perigosamente o acoplamento entre os módulos de punição e o núcleo de regras do pet.

Para solucionar esse problema e permitir uma espécie de "viagem no tempo" focada na recuperação de progresso, foi adotado o padrão comportamental **Memento (GoF)** ([GAMMA et al., 1995; SHVETS, 2021](../Relatórios/1.1.3.SubEquipe_03.md#referências)). O padrão permite capturar o estado dinâmico do `PetVirtual` (*Originator*) em um momento específico sem expor sua estrutura íntima de funcionamento. Esses dados vitais são salvos como uma "fotografia" imutável em um `MementoPet` (*Memento*), enquanto a linha do tempo e a organização cronológica desses salvamentos ficam sob total responsabilidade de controle do `HistoricoPet` (*Caretaker*). Dessa forma, o sistema pode congelar instantes do pet ou desfazer alterações de maneira íntegra, segura e completamente desacoplada do restante da aplicação.

##### Modelagem (Notação UML)

A modelagem orientada a objetos foi arquitetada para garantir a blindagem estrutural dos dados, separando claramente as responsabilidades de quem gera o estado e de quem o armazena.

Conforme demonstrado no diagrama de classes, o padrão é orquestrado por três papéis fundamentais:
*   **Originator (`PetVirtual`):** Alocado no pacote de domínio, é a entidade que possui o estado vivo e mutável (nível, experiências, peso). Ela é a única com autorização para instanciar um *Memento* de si mesma (via `criarMemento`) e restaurar seus próprios dados a partir de um *snapshot* recebido (via `restaurarMemento`).
*   **Memento (`MementoPet`):** Representa o cofre de dados blindado. Seus atributos refletem as propriedades do pet no exato instante do salvamento. Por ser imutável após instanciado, ele expõe apenas métodos de leitura (*getters*), garantindo que outras partes do sistema não corrompam o backup.
*   **Caretaker (`HistoricoPet`):** Gerencia ativamente a coleção de backups sem jamais inspecionar ou alterar seus conteúdos. Ele mantém uma agregação de objetos `MementoPet` em uma lista (com limite de 10 registros para eficiência e otimização de memória), solicitando a criação de backups e coordenando a devolução desses estados ao pet quando um "desfazer" é acionado.

##### Implementação (Código & Vídeo com Padrão em Execução)

A transição da modelagem para o código-fonte em Java refletiu o rigor da separação de responsabilidades. O código foi particionado nos pacotes app, dominio, memento e state, resguardando a coesão técnica e garantindo fácil rastreabilidade.

A implementação destaca-se pelo cuidado com a segurança da memória e dos tipos primitivos. Na classe MementoPet, ao encapsular as matrizes do pet (como o histórico de experienciasPorCategorias), é realizada uma cópia profunda (Deep Copy) via Arrays.copyOf. Essa técnica blinda o snapshot contra modificações acidentais, evitando que o estado arquivado vaze ou sofra mutações se o array original do pet for alterado futuramente.

O HistoricoPet sustenta uma arquitetura de fila rotativa que absorve o acúmulo de backups sem impactar o desempenho do sistema, e descarta o estado mais primitivo caso a constância de registros exceda o teto paramétrico de 10 limites.

A classe Main orquestra e prova o fluxo de ponta a ponta: ela constrói um avatar, instiga o acúmulo de XP contínuo, exige que o Caretaker arquive uma fotografia de segurança imediata, aplica uma pesada dedução no progresso por penalidade e, por fim, força uma intervenção de restabelecimento que extrai os atributos recém-protegidos e os injeta de volta na raiz do Originator, comprovando o fluxo e atestando que os preceitos de arquitetura orientada a objetos mantêm a essência da abstração intacta.

```java
import dominio.CategoriaXP;

import memento.HistoricoPet;

public class Main {
    public static void main(String[] args) {
        System.out.println("=== EXECUÇÃO INDIVIDUAL: PADRÃO MEMENTO ===\n");

        PetVirtual pet = new PetVirtual("Tamagoshi");
        HistoricoPet caretaker = new HistoricoPet();

        System.out.println("--- 1. Estado Inicial ---");
        System.out.println(pet);
        
        System.out.println("\n--- 2. Progresso do Pet ---");
        pet.acumularExperiencia(CategoriaXP.SABEDORIA, 150.0f);
        pet.acumularExperiencia(CategoriaXP.INTELECTUAL, 50.0f);
        System.out.println(pet);

        System.out.println("\n--- 3. Salvando Snapshot de Segurança ---");
        // O Cliente orquestra: Pede ao Originator para criar o Memento e passa para o Caretaker guardar
        MementoPet snapshotSeguranca = pet.salvarEstado("Backup pré-quebra de ofensiva");
        caretaker.adicionarMemento(snapshotSeguranca);

        System.out.println("\n--- 4. Penalidade Sofrida ---");
        pet.sofrerPenalidadeXP(120.0f);
        System.out.println(pet);

        System.out.println("\n--- 5. Restaurando o Estado (Acionando o Memento) ---");
        // O Cliente orquestra: Pede o Memento ao Caretaker e repassa ao Originator
        MementoPet mementoRecuperado = caretaker.getUltimoMemento();
        if (mementoRecuperado != null) {
            pet.restaurarEstado(mementoRecuperado);
        }
        
        System.out.println("\n--- 6. Estado Final ---");
        System.out.println(pet);
    }
}
```

```java
package dominio;

import memento.MementoPet;
import state.EstadoPet;

public class PetVirtual {
    private String nomePet;
    private int nivel;
    private int peso;
    private float[] experienciasPorCategorias = new float[5];
    private float experienciaTotal;
    private EstadoPet estadoAtual;

    public PetVirtual(String nomePet) {
        this.nomePet = nomePet;
        this.nivel = 1;
        this.peso = 5;
        this.experienciaTotal = 0.0f;
    }

    public void acumularExperiencia(CategoriaXP categoria, float pontosXp) {
        this.experienciaTotal += pontosXp;
        System.out.println("[" + nomePet + "] Acumulou " + pontosXp + " XP na categoria " + categoria);
    }

    // =========== MEMENTO (Originator) ===========

    public MementoPet salvarEstado(String motivo) {
        System.out.println("Originator: Salvando estado no Memento. Motivo: " + motivo);
        return new MementoPet(nivel, peso, experienciasPorCategorias, 
                              experienciaTotal, estadoAtual, motivo);
    }

    public void restaurarEstado(MementoPet memento) {
        this.nivel = memento.getNivel();
        this.peso = memento.getPeso();
        this.experienciasPorCategorias = memento.getExperienciasPorCategorias();
        this.experienciaTotal = memento.getExperienciaTotal();
        this.estadoAtual = memento.getEstadoAtual();
        
        System.out.println("Originator: Estado restaurado após usar Memento. Retornado ao ponto: " + memento.getMotivo());
    }

    // Modificador extra para simular perda de progresso
    public void sofrerPenalidadeXP(float pontosPerdidos) {
        this.experienciaTotal -= pontosPerdidos;
        System.out.println("[" + nomePet + "] Sofreu penalidade de " + pontosPerdidos + " XP.");
    }
    
    @Override
    public String toString() {
        return "PetVirtual {nome='" + nomePet + "', nivel=" + nivel + ", expTotal=" + experienciaTotal + "}";
    }
}
```

```java
package memento;

import java.util.ArrayList;
import java.util.List;

public class HistoricoPet {
    private final List<MementoPet> mementos = new ArrayList<>();
    private final int limiteSnapshots = 10;

    public void adicionarMemento(MementoPet memento) {
        if (mementos.size() >= limiteSnapshots) {
            mementos.remove(0); 
        }
        mementos.add(memento);
        System.out.println("Caretaker: Snapshot armazenado com segurança.");
    }

    public MementoPet getUltimoMemento() {
        if (!mementos.isEmpty()) {
            return mementos.remove(mementos.size() - 1);
        }
        System.out.println("Caretaker: Nenhum histórico disponível.");
        return null;
    }
    
    public MementoPet getMemento(int index) {
        if (index >= 0 && index < mementos.size()) {
            return mementos.get(index);
        }
        return null;
    }
}
```

```java
package memento;

import state.EstadoPet;
import java.time.LocalDateTime;
import java.util.Arrays;

public class MementoPet {
    private final int nivel;
    private final int peso;
    private final float[] experienciasPorCategorias;
    private final float experienciaTotal;
    private final EstadoPet estadoAtual;
    private final LocalDateTime dataHoraSnapshot;
    private final String motivo;

    public MementoPet(int nivel, int peso, float[] experienciasPorCategorias, 
                      float experienciaTotal, EstadoPet estadoAtual, String motivo) {
        this.nivel = nivel;
        this.peso = peso;
        // Cópia profunda para blindar o estado salvo contra modificações externas
        this.experienciasPorCategorias = experienciasPorCategorias != null 
            ? Arrays.copyOf(experienciasPorCategorias, experienciasPorCategorias.length) 
            : new float[5];
        this.experienciaTotal = experienciaTotal;
        this.estadoAtual = estadoAtual;
        this.dataHoraSnapshot = LocalDateTime.now();
        this.motivo = motivo;
    }

    public int getNivel() { return nivel; }
    public int getPeso() { return peso; }
    public float[] getExperienciasPorCategorias() { 
        return Arrays.copyOf(experienciasPorCategorias, experienciasPorCategorias.length); 
    }
    public float getExperienciaTotal() { return experienciaTotal; }
    public EstadoPet getEstadoAtual() { return estadoAtual; }
    public LocalDateTime getDataHoraSnapshot() { return dataHoraSnapshot; }
    public String getMotivo() { return motivo; }
}
```
